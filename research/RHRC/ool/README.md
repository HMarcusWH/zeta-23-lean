## RHKG Phase Atlas

The post-#265 adapter does **not** treat a theorem module, type hash, graph
neighbourhood, or FFBBP cohort as a mathematical handoff. It takes the exact
680 `SOURCE_ONLY_PUBLIC_THEOREM` Lean declarations and extracts a separate
DISCOVERY_ONLY compiler dependency closure rooted at those declarations.

The first Phase Atlas intentionally uses the existing
`THEOREM_VALUE_ERASED_SUPPORT` projection:

- theorem proof-body VALUE edges are erased;
- TYPE and STRUCTURE edges remain;
- VALUE edges of non-theorem support declarations remain;
- only local `Zeta23.*` declaration contacts are used for interface
  classification.

Three disjoint registered-claim anchor families define the live research
interfaces: carrier/spectrum, aperture/arithmetic, and ground/source. Support
shared by multiple families is removed before a contact can count as
interface-distinctive. This prevents generic common infrastructure from
manufacturing a fake cross-interface signal.

The atlas separately checks contact with the exact #261 theorem-value-erased
21-edge arithmetic frontier. Such contact is a **LEAD / discovery surface**,
not theorem composition and not RH evidence.
