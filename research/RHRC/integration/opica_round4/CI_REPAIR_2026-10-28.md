### Explicit compiler thread pool

At `a527b8e1`, the real Linux CONTRACT lane passes the checkout regression.
Native preparation then reaches the production standard-library smoke and exits
with `failed to create thread` before the project build. Its recorded command
sets `LEAN_NUM_THREADS=2` but has no explicit compiler thread-count option.

The pinned Lean shell defaults to hardware concurrency and initializes its task
manager from that shell option. Its 64-bit runtime defaults each thread stack to
1 GiB, so the default pool can exhaust the worker's 4 GiB address-space budget.
The short failure log does not establish the precise `pthread_create` errno.
Both production and development recipes now bind the actual compiler pool with
`-j2`; memory, CPU, process, output and disk caps and namespace isolation remain
unchanged. Exact-command reconstruction includes this flag. Production startup,
the full native lanes and independent aggregation must still execute and pass.
