## 30 October: independent acceptance memory residency

At exact head `3cf99b4ea74209bba372beca7c66e5150ee6fa4c`, run
`40893232364` completed all eleven producer lanes successfully. Its independent
acceptance job `123637302670` failed in the reconstruction step. The actual
systemd receipt says `oom-kill`, memory peak `4.0G`, zero swap, and service
runtime `4h 3min 6.977s`. This establishes an aggregate service memory failure;
it does not establish a theorem rejection, the active lane, or the allocating
process. The original diagnostic artifact retained bootstrap evidence only.

The source exposed a cumulative residency problem: all independent native
lanes and both test modes used the same persistent tmpfs while the coordinator,
Lean workers and later canonical materializer shared a hard 4 GiB cgroup.
Completed attempt and import-inventory files remained memory-resident when the
next lane started. Streaming file hashing was already present; no evidence of
a cross-lane Python cache leak was found. The precise final allocation in the
failed job remains unobserved.

Acceptance now gives each native lane its own freshly owned tmpfs subtree.
After the complete independent replay succeeds, it seals and copies every file
and directory to a disjoint ordinary evidence filesystem, packs that exact
tree into the existing closed stored transport, verifies the retained copy,
and retires only the caller-owned scratch subtree. The transport inside the
acceptance artifact retains dot entries and empty directories. Its raw disk
copy also remains until runner cleanup. Bootstrap/configuration and producer
bundles are preserved. Disk admission rejects the native volume, tmpfs and
ramfs archives; disk headroom is observed because retained raw and transport
copies consume ordinary evidence storage.

Reclamation uses private creation identities, complete source/archive reseals,
no-follow parent handles and authenticated leaf deletion. Windows deletes the
opened leaf handle; Linux uses descriptor-relative unlink/rmdir after checking
the leaf. Lane workers have completed before reclamation. Copy, pack, archive
verification and cleanup failures propagate and cannot produce acceptance.
The original exception survives optional failure diagnostics.

Fixed, flushed lane/mode/subphase diagnostics and an external bounded observer
now record memory categories, cgroup events, shared tmpfs usage and disk
headroom. The observer remains outside the service's cgroup so service OOM can
leave evidence; its output has no acceptance authority. Its exit trap preserves
the original service result. Missing or collected unit state stays explicit.

All eleven independent recipes, normal/optimized modes, fresh source/import
hashes, compiler/consumer/axiom gates and attempt bindings remain mandatory.
The 4 GiB physical memory and active tmpfs limits, no-swap policy, process/CPU,
file/log/wall limits and namespaces are unchanged. No mathematical source or
compiler pin changes. Local portable/structural validation is distinct from
the mandatory fresh Linux qualification of this repair. RH and Step4 remain
OPEN.

### Explicit compiler thread pool

At `a527b8e1`, the real Linux CONTRACT lane passes the checkout regression.
Native preparation then reaches the production standard-library smoke and exits
with `failed to create thread` before the project build. Its recorded command
sets `LEAN_NUM_THREADS=2` but has no explicit compiler thread-count option.

The pinned Lean shell defaults to hardware concurrency and initializes its task
manager from that shell option. Its 64-bit runtime defaults each thread stack to
1 GiB, so the default pool can exhaust the worker's 4 GiB address-space budget.
The short failure log does not establish the precise `pthread_create` errno.
Both production and development recipes now bind the actual compiler pool with
`-j2`; memory, CPU, process, output and disk caps and namespace isolation remain
unchanged. Exact-command reconstruction includes this flag. Production startup,
the full native lanes and independent aggregation must still execute and pass.
